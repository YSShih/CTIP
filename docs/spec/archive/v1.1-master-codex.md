| 里程碑 | 涵蓋 Phase | 目標 | 驗收依據 |
|---|---|---|---|

**Coding LLM 必須一次只推進一個里程碑。** 未通過 DoD-MVP 之前，不得開始 Phase 13 之後的任何工作，不得為了「符合最終規格」而預先建立 Kafka / Elasticsearch / 通知相關程式碼。

本文件每一節標註其所屬 Phase，例如 `[Phase 4 · M1]`。標註為 `[M2]` 或 `[M3]` 的章節，在 M1 階段**只需保留擴充點（介面 / port），不得實作**。

# 3. MASTER ARCHITECTURE

## 3.1 Architectural Principles

Backend MUST follow:

- Domain Driven Design
- Clean Architecture / Hexagonal Architecture（Ports and Adapters）
- Event Driven Architecture（M3）
- SOLID / Dependency Inversion
- Explicit boundaries、High cohesion、Low coupling

**不採用 CQRS。** v1.0 的「where justified」在實務上會被 Coding LLM 過度解讀。讀寫分離的需求由 Elasticsearch 讀取索引（§30）自然滿足，不需要額外的 CQRS 框架。

Frontend MUST follow:

- Feature-based architecture
- Separation of UI / state / API / domain models
- Server state 與 client state 分離
- Typed API contracts（由 OpenAPI 產生）
- Reusable component system

Infrastructure MUST follow:

- Environment configuration separation
- Immutable production images
- Infrastructure-as-code friendly structure
- 單一 compose 定義，無重複
- Secrets 永不進版控

## 3.2 分層依賴方向（強制）

```text
interfaces  →  application  →  domain
     ↓              ↓            ↑
infrastructure ─────────────────┘
                (實作 domain 定義的 port)
```

- `domain` 不得 import 任何 Spring、JPA、Jackson、Kafka、Redis 類別
- `application` 可 import Spring 的 `@Service` / `@Transactional`，不得 import JPA Entity
- `infrastructure` 實作 `domain` 宣告的介面
- `interfaces` 只做 HTTP/WS 協定轉換與 DTO 映射

CI 必須有一條 ArchUnit 測試驗證上述規則（§52.4）。

# 5. ENVIRONMENT CONTRACT

## 5.1 唯一的 Compose 檔

專案必須支援四種 profile：`mvp`、`dev`、`staging`、`prod`。

**只能有一個 compose 檔：**

```text
environment/docker-compose.yml
```

**禁止建立：**

```text
docker-compose.dev.yml
docker-compose.staging.yml
docker-compose.prod.yml
docker-compose.mvp.yml        ← v1.0 的例外已取消
docker-compose.override.yml
```

環境差異一律透過**環境變數**與 **Compose profiles** 控制。

## 5.2 兩種控制機制的分工（強制）

| 要控制的事 | 機制 |
|---|---|
| **這個服務要不要啟動**（Kafka / ES / Redis / 監控） | `profiles:` + `COMPOSE_PROFILES` 環境變數 |
| **這個服務怎麼跑**（build target、mount、port、JVM 參數、restart policy） | 環境變數 |

## 5.3 Mount 的變數化（關鍵技巧）

Compose 的 `volumes:` 區段**無法用環境變數整段消失**。解法是讓 source、target、mode 三者都變成變數，正式環境掛一個無害的空目錄：

```yaml
volumes:
  - ${BACKEND_MOUNT_SRC:-./.noop}:${BACKEND_MOUNT_DST:-/opt/noop}:${BACKEND_MOUNT_MODE:-ro}
```

- 本機開發：`../backend` → `/workspace`（rw），支援 hot reload
- staging / prod：使用預設值，掛 `environment/.noop` 到 `/opt/noop`（唯讀、空目錄，完全不影響映像檔內容）

`environment/.noop/.gitkeep` **必須 commit**。

## 5.4 防呆檢查（強制）

CI 必須包含一條檢查：在 prod 設定下，`docker compose config` 的輸出不得包含 `../backend` 或 `../frontend`。

```bash
docker compose --env-file environment/.env.prod.example \
  -f environment/docker-compose.yml config \
  | grep -E '\.\./(backend|frontend)' && exit 1 || exit 0
```

`.env.prod.example` 與 `.env.staging.example` 中**不得出現任何 `*_MOUNT_*` 變數**（依賴預設值）。

# 7. DOCKERFILE CONTRACT

只能有：

```text
environment/docker/backend/Dockerfile
environment/docker/frontend/Dockerfile
```

禁止 `Dockerfile.dev` / `Dockerfile.staging` / `Dockerfile.prod`。

以 **multi-stage build + `target`** 區分行為。因為 dev 與 prod 是不同 stage，**連 `command:` 都不需要在 compose 中切換**。

## 7.1 Backend Dockerfile 骨架

```dockerfile
# syntax=docker/dockerfile:1.7

########## development ##########
FROM eclipse-temurin:25-jdk AS development
WORKDIR /workspace
ENV SPRING_DEVTOOLS_RESTART_ENABLED=true
EXPOSE 8080 5005
CMD ["./mvnw", "-pl", "ctip-app", "-am", "spring-boot:run"]

########## build ##########
FROM eclipse-temurin:25-jdk AS build
WORKDIR /src
COPY .mvn/ .mvn/
COPY mvnw pom.xml ./
COPY ctip-sdk/pom.xml      ctip-sdk/
COPY ctip-core/pom.xml     ctip-core/
COPY ctip-adapters/pom.xml ctip-adapters/
COPY ctip-app/pom.xml      ctip-app/
RUN --mount=type=cache,target=/root/.m2 ./mvnw -B -q dependency:go-offline
COPY . .
RUN --mount=type=cache,target=/root/.m2 ./mvnw -B -DskipTests package

########## production ##########
FROM eclipse-temurin:25-jre AS production
RUN useradd -r -u 10001 ctip
WORKDIR /app
COPY --from=build /src/ctip-app/target/*.jar app.jar
USER ctip
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s --start-period=60s \
  CMD ["java", "-version"]
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

## 7.2 Frontend Dockerfile 骨架

```dockerfile
# syntax=docker/dockerfile:1.7

########## development ##########
FROM node:24-alpine AS development
WORKDIR /workspace
EXPOSE 5173
CMD ["npm", "run", "dev", "--", "--host", "0.0.0.0"]

```

# 9. TECHNOLOGY STACK

## 9.1 版本政策（強制）

1. **一律使用「有長期支援且已 GA」的版本**，不使用 beta / RC / preview。
2. 凡是 Spring Boot BOM 已納管的相依（Flyway、Testcontainers、Jackson、Hibernate、PostgreSQL JDBC、Lettuce、Micrometer、spring-kafka⋯），**不得在 `pom.xml` 中硬寫版本號**，一律由 BOM 決定。刻意覆寫時必須在 `pom.xml` 加註解說明原因。
3. 不由 BOM 納管的相依（springdoc、MapStruct、Lombok、Resilience4j、Bucket4j⋯）必須在 parent pom 的 `<properties>` 中集中定義版本。
4. 前端一律使用 `package-lock.json` 鎖定，CI 用 `npm ci`。
5. 啟用 Dependabot 或 Renovate（§53.3）。

## 9.3 Lombok 使用政策（強制縮減）

Java 25 已有 `record`、pattern matching。Lombok 是使用 JDK 內部 API 的第三方工具，每次 JDK 升級都是風險點。

**只允許使用：**

- `@Slf4j`
- `@RequiredArgsConstructor`（僅限 Spring bean 的建構子注入）

**禁止使用：**

- `@Data`、`@Setter`、`@Getter`（domain 物件用 `record`；JPA entity 手寫 getter）
- `@Builder`（用 `record` 的靜態工廠或手寫 builder）
- `@AllArgsConstructor`、`@NoArgsConstructor`
- `@EqualsAndHashCode`、`@ToString`

## 9.4 TypeScript 7 注意事項

TypeScript 7 是以 Go 重寫的編譯器，效能大幅提升，但：

- 部分舊型別定義套件可能尚未相容
- **若在 M1 階段遇到生態系相容性問題，允許降級至 TypeScript 5.9.x，並在 `docs/development/` 記錄原因**
- 這是本規格中唯一允許主動降版的套件

## 9.6 已知編譯地雷（必讀）

### 9.6.1 JDK 23+ 預設關閉 annotation processing

JDK 23 起 `javac` 預設 `-proc:none`。使用 Lombok / MapStruct 時**必須明確開啟**，否則會出現 `cannot find symbol`。

### 9.6.2 Lombok + MapStruct 處理器順序

順序錯誤會產生**空的 mapper 實作**（編譯成功但 runtime 全是 null）。

parent `pom.xml` 必須包含：

```xml

  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration>
    <release>25</release>
    <proc>full</proc>
    <compilerArgs>
      <arg>-parameters</arg>
      <arg>-Xlint:all</arg>
    </compilerArgs>
    <annotationProcessorPaths>
      <path>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <version>${lombok.version}</version>
      </path>
      <path>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok-mapstruct-binding</artifactId>
        <version>0.2.0</version>
      </path>
      <path>
        <groupId>org.mapstruct</groupId>
        <artifactId>mapstruct-processor</artifactId>
        <version>${mapstruct.version}</version>
      </path>
    </annotationProcessorPaths>
  </configuration>
</plugin>
```

`-parameters` 為 springdoc 正確推導參數名稱所必需。

# 12. THREAT INTELLIGENCE INGESTION  `[Phase 6 · M1]`

## 12.1 Pipeline

```text
Threat Source
     ↓  Adapter            (ctip-adapters)
Raw Threat Record
     ↓  Parser             (source-specific)
     ↓  Validator          (§31 資料品質，reject malformed)
     ↓  Normalizer         (canonical value)
     ↓  Fingerprint        (SHA-256 of canonical value)
Domain Indicator (candidate)
     ↓  Deduplication      (查既有 indicator)
     ↓  Merge              (IndicatorMergePolicy §19)
     ↓  STIX Mapping
     ↓  Persistence        (PostgreSQL — source of truth)
     ↓  Bloom Update                                          [M2]
     ↓  Search Index       (Elasticsearch)                    [M2]
     ↓  Domain Event → Kafka                                  [M3]
     ↓  Notification / Sync trigger                           [M3]
```

## 12.2 實作方式：明確的 Stage 串接（非 Template Method）

**禁止使用抽象基底類別 + 繼承來實作 pipeline。** 改用組合：

```java
public interface IngestionStage {
    String name();
    IngestionContext execute(IngestionContext context);
}
```

`IngestionPipeline` 持有 `List<IngestionStage>`，依註冊順序執行。理由：

- 順序在一個地方看得完整，不需要追繼承鏈
- 每個 stage 可獨立單元測試
- 新增 stage 不需修改既有類別
- 每個 stage 的耗時與失敗率可獨立度量（§51）

## 12.3 批次與交易邊界

- 外部抓取（adapter fetch）**絕不包在資料庫交易內**
- 抓取完成後以固定批次大小（預設 500 筆）進入 pipeline，每批一個交易
- 單筆失敗只丟棄該筆並記錄，不使整批 rollback
- 每次 ingestion 產生一筆 `source_sync` 記錄（成功數／失敗數／耗時）

## 15.1 架構須支援

## 15.2 再散布政策（法遵，強制）  `[Phase 4 · M1]`

⚠️ **多數商業情資來源的服務條款禁止再散布原始資料**（例如 VirusTotal、AbuseIPDB 的部分方案）。本平台提供對外 API，因此必須在資料層追蹤此限制。

`sources` 表與 `indicator_sources` 表都必須有：

```text
redistribution_policy:
  PUBLIC_REDISTRIBUTABLE   可原樣對外提供
  ATTRIBUTION_REQUIRED     可提供，但回應中必須附上來源標註
  DERIVED_ONLY             只能提供衍生結果（可回答「此 IP 有風險」，不得回傳原始記錄與來源明細）
  INTERNAL_ONLY            不得對外輸出，僅供內部比對
```

規則：

1. `indicator_sources` 在 ingestion 當下**快照**該來源的政策（來源條款會變，歷史資料須依當時政策處理）
2. API 輸出層依政策過濾或遮罩，此邏輯必須集中在一個 `RedistributionFilter`，不得散落各 controller
3. 若某 IOC 的所有來源皆為 `INTERNAL_ONLY`，該 IOC 不得出現在任何對外 API 或 Bloom filter 中
4. `ATTRIBUTION_REQUIRED` 的資料，API 回應必須含 `attribution` 欄位

# 16. STIX 2.1 與 TLP  `[Phase 8 · M1]`

## 16.1 支援的 STIX 物件

- `malware`
- `attack-pattern`

## 16.2 TLP 2.0（新增，強制）

TLP 是整個「匿名／付費」分級的**資料層依據**。沒有它，無法定義什麼叫「公開情資」。

```text
Tlp: CLEAR | GREEN | AMBER | AMBER_STRICT | RED
```

### 可見度矩陣

| 存取者 | 可見 TLP |
|---|---|
| 匿名 | `CLEAR` |
| 已登入 Free | `CLEAR`, `GREEN` |
| Premium | `CLEAR`, `GREEN` |
| Tenant 成員 | 上述 + 自家 tenant 的 `AMBER`, `AMBER_STRICT` |
| `RED` | 不進入平台。若必須存放，需明確授權紀錄與獨立稽核 |

### 實作要求

- TLP 過濾**必須在 repository / query 層強制執行**，不得依賴 controller 自律
- 使用 JPA `Specification` 統一附加 TLP 條件
- 必須有一組安全測試（§52.5）驗證：匿名身分無論如何都拿不到非 `CLEAR` 資料

### 合併規則

一個 IOC 有多個來源時，取**最嚴格**的 TLP（`CLEAR` < `GREEN` < `AMBER` < `AMBER_STRICT` < `RED`）。

# 17. IOC MODEL  `[Phase 4 · M1]`

## 17.1 型別

```text
IocType: IPV4 | IPV6 | DOMAIN | URL | FILE_HASH | EMAIL
```

`FILE_HASH` 搭配 `IocHashType` 說明演算法（見 §20）。

> v1.0 把 MD5/SHA1/SHA256/SHA512 直接列為 IOC type。改為 `FILE_HASH` + `hash_type` 更貼近 STIX，也避免與去重指紋混淆。

## 17.2 欄位

```text
Indicator
  id                UUID
  type              IocType
  hash_type         IocHashType      (僅 FILE_HASH 使用，其餘為 null)
  value             String           原始值（保留來源樣貌）
  normalized_value  String           正規化後的 canonical value
  fingerprint       String           SHA-256(normalized_value)，去重用
  first_seen        Instant
  last_seen         Instant
  valid_from        Instant
  valid_until       Instant          可為 null（永不過期）
  confidence        Integer          0-100，聚合後
  severity          Severity         INFO | LOW | MEDIUM | HIGH | CRITICAL
  score             Integer          0-100，由 ThreatScorer 計算
  tlp               Tlp              取所有來源中最嚴格者
  status            IndicatorStatus
  tags              Set<String>
  owner_tenant_id   UUID             公開情資為 public tenant
  created_at        Instant
  updated_at        Instant
```

```text
IndicatorStatus: ACTIVE | EXPIRED | REVOKED | FALSE_POSITIVE
```

## 17.3 唯一性

```sql
UNIQUE (type, normalized_value, owner_tenant_id)
```

`fingerprint` 另建索引，供快速查詢與 Bloom 生成使用。

## 17.4 過期機制（新增）

各型別的預設 TTL（來源可覆寫）：

| 型別 | 預設 TTL |
|---|---|
| `IPV4` / `IPV6` | 30 天 |
| `DOMAIN` | 90 天 |
| `URL` | 90 天 |
| `EMAIL` | 90 天 |
| `FILE_HASH` | 不過期（`valid_until = null`） |

TTL 從 `last_seen` 起算。每次有新來源回報同一 IOC，`last_seen` 更新並順延 `valid_until`。

排程任務每日將 `valid_until < now()` 且 `status = ACTIVE` 的記錄改為 `EXPIRED`（§34）。`EXPIRED` 的 IOC 不進入 Bloom filter，API 預設不回傳（可用 `?includeExpired=true` 查詢）。

# 19. DEDUPLICATION 與 MULTI-SOURCE MERGE  `[Phase 7 · M1]`

## 19.1 識別鍵

去重的唯一依據：

```text
(type, normalized_value, owner_tenant_id)
```

`fingerprint = SHA-256(normalized_value)` 僅作為索引與 Bloom 成員，**不是**識別鍵（避免碰撞造成資料合併錯誤）。

## 19.2 每來源記錄

`indicator_sources` 保存每個來源各自回報的值，**不覆寫**：

```text
indicator_sources
  id                       UUID
  indicator_id             UUID    FK
  source_id                UUID    FK
  source_confidence        Integer
  source_severity          Severity
  source_tlp               Tlp
  source_first_seen        Instant
  source_last_seen         Instant
  source_valid_until       Instant
  redistribution_policy    RedistributionPolicy    (ingestion 當下的快照)
  raw_payload              JSONB
  status                   SourceRecordStatus      ACTIVE | EXPIRED | RETRACTED | FALSE_POSITIVE
  created_at               Instant
  updated_at               Instant

UNIQUE (indicator_id, source_id)
```

## 19.3 IndicatorMergePolicy（強制，單一類別）

聚合規則必須集中在 `com.ctip.domain.indicator.IndicatorMergePolicy`，並有完整單元測試：

| 欄位 | 聚合規則 |
|---|---|
| `first_seen` | `MIN(source_first_seen)` |
| `last_seen` | `MAX(source_last_seen)` |
| `valid_until` | `MAX(source_valid_until)`；任一來源為 null 則為 null |
| `confidence` | 依來源信譽加權平均；獨立 ACTIVE 來源數 ≥ 3 時 `+10`，上限 100 |
| `severity` | `MAX`（依 INFO < LOW < MEDIUM < HIGH < CRITICAL 排序） |
| `tlp` | 最嚴格者 |
| `tags` | 聯集 |
| `status` | 見下方規則 |

### status 判定順序

1. 任一來源 `status = RETRACTED` 且該來源信譽 ≥ 80 → `REVOKED`
2. 任一來源 `FALSE_POSITIVE` 且無其他 `ACTIVE` 來源 → `FALSE_POSITIVE`
3. 所有來源皆 `EXPIRED` → `EXPIRED`
4. 其他 → `ACTIVE`

## 19.4 來源信譽

`sources.reputation`（0-100，預設 50）由管理員設定，是加權平均的權重。M1 使用固定值即可。

# 20. FINGERPRINT 與 HASH（命名釐清）  `[Phase 7 · M1]`

# 21. BLOOM FILTER  `[Phase 15 · M2]`

## 21.1 目的與語意

讓 Browser Extension / App 能以極低成本判斷某 IOC **是否可能**存在於情資集合中。

```text
Bloom 說 NOT PRESENT → 一定不存在
Bloom 說 PRESENT     → 可能存在 → 必須再呼叫 API 精確驗證
```

**系統絕不得將 Bloom 命中視為「確定惡意」。** API 文件、SDK 文件、前端 UI 都必須明確說明此點。

## 21.2 兩層架構（新增，解決 per-tenant 成本）

v1.0 要求「每個 tenant 一份 Bloom」。以 10M 容量 @ 0.1% FPR 計算，單份約 18 MB；100 個 tenant 每次重建就是 1.8 GB。改為兩層：

```text
public bloom   ← 所有 TLP:CLEAR 且 redistribution 允許的 IOC
                 全體共用一份，可放 CDN，無 tenant 隔離問題

tenant bloom   ← 僅含該 tenant 的私有 IOC（AMBER / AMBER_STRICT）
                 通常小兩到三個數量級
```

Client 同時查兩份，任一命中即走 API 精確驗證。

## 21.3 Bloom 無法刪除元素（必須明文說明）

標準 Bloom filter **不支援移除成員**。因此：

```text
delta = 從 baseVersion 到 targetVersion 之間「新增」的 bit 索引集合
撤銷（REVOKED）或過期（EXPIRED）的 IOC 無法透過 delta 移除
移除只能靠 full snapshot 重建
```

### 快照政策

| 項目 | 值 |
|---|---|
| Full snapshot | 每日一次（`datasetVersion` +1） |
| Delta | 日內每小時一次（`bloomVersion` +1） |
| 強制重下 full 的條件 | delta 鏈 > `BLOOM_MAX_DELTA_CHAIN`（預設 24 段）**或** 累計 delta 大小 > full 的 30% |

超過條件時，伺服器對 `GET /api/v1/sync/delta` 回應：

```json
{ "status": 409, "code": "SNAPSHOT_REQUIRED", "message": "Delta chain too long, download full snapshot" }
```

## 21.4 Metadata

```text
BloomVersion
  id                    UUID
  scope                 PUBLIC | TENANT
  tenant_id             UUID       (scope=PUBLIC 時為 public tenant)
  dataset_version       long
  bloom_version         long
  fingerprint_algorithm FingerprintAlgorithm
  hash_function_count   int        (k)
  bit_size              long       (m)
  capacity              long       (n)
  false_positive_rate   double
  member_count          long
  checksum              String     SHA-256 of the bit array
  size_bytes            long
  compression           GZIP | ZSTD | NONE
  generated_at          Instant
```

## 21.5 下載回應

```json
{
  "scope": "PUBLIC",
  "datasetVersion": 128,
  "bloomVersion": 42,
  "fingerprintAlgorithm": "SHA256",
  "hashFunctionCount": 7,
  "bitSize": 143775876,
  "capacity": 10000000,
  "falsePositiveRate": 0.001,
  "memberCount": 8342119,
  "checksum": "sha256:...",
  "sizeBytes": 17971985,
  "compression": "ZSTD",
  "downloadUrl": "https://.../bloom/public/42.bin.zst",
  "expiresAt": "2026-08-22T00:00:00Z"
}
```

下載 URL 必須依方案授權（§23.2）。

## 21.6 相容性

Client 必須能偵測不相容：若 `fingerprintAlgorithm`、`hashFunctionCount`、`bitSize` 任一改變，舊的本地 Bloom 立即作廢，必須重下 full。

## 22.1 流程

# 25. MULTI-TENANT  `[Phase 4 · M1 資料模型；M2 強制隔離]`

# 27. JWT SECURITY  `[Phase 13 · M2]`

支援：access token、refresh token、過期、撤銷策略、密碼雜湊、登入稽核。

| 項目 | 規格 |
|---|---|
| 演算法 | HS256（單體）；預留 RS256 供未來多服務使用 |
| Access token | 預設 15 分鐘 |
| Refresh token | 預設 30 天，**單次使用並輪替**（rotation） |
| Refresh token 儲存 | 資料庫存雜湊值，不存原文 |
| 撤銷 | refresh token 撤銷清單；access token 短命，不做黑名單 |

| 密碼雜湊 | BCrypt（cost 12）或 Argon2id |

`JWT_SECRET` 必須來自環境設定，長度 ≥ 32 bytes。**絕不 commit。** 應用啟動時若偵測到 `JWT_SECRET` 為預設樣板值且 `ENVIRONMENT=prod`，必須拒絕啟動。

# 31. DATA QUALITY  `[Phase 6 · M1]`

## 31.1 正規化規則

| 型別 | 規則 |
|---|---|
| 共通 | 去除前後空白、移除零寬字元 |
| `IPV4` | 驗證後轉為標準點分十進位；拒絕保留位址（除非來源明示） |
| `IPV6` | 依 RFC 5952 壓縮，小寫 |
| `DOMAIN` | 小寫、去除尾端點、IDN 轉 punycode、去除 `www.` 前綴需可設定 |
| `URL` | scheme/host 小寫、預設 port 移除、路徑百分比編碼正規化、排序 query 參數、移除 fragment |
| `FILE_HASH` | 小寫十六進位；依長度驗證（MD5=32、SHA1=40、SHA256=64、SHA512=128） |
| `EMAIL` | domain 部分小寫 |

## 31.2 拒絕規則

必須**拒絕**並記錄，不得靜默接受：

- 格式不合的值
- 私有／保留 IP（10/8、172.16/12、192.168/16、127/8、169.254/16、::1 等），除非來源 metadata 明示允許
- 常見的良性大型服務網域（可設定的 allowlist，例如 google.com、microsoft.com）
- 長度異常（URL > 2048、domain > 253）
- 雜湊長度與宣告演算法不符

拒絕的記錄寫入 `ingestion_rejections` 表（含原因），供品質分析。

# 35. DESIGN PATTERNS（可維護、可讀優先）

> v1.0 同時要求「必須展示 10 種模式」與「不得硬塞模式」，兩者衝突。以下改為三類，並給出單一判準。

## 35.0 判準（強制）

> **若移除某個抽象之後，程式仍然只有一種可能的實作，就不要加這個抽象。**

## 35.1 必須使用（解決真實問題）

| 模式 | 用於 | 為何不可省 |
|---|---|---|
| **Adapter** | `ThreatSourceAdapter` | 每個情資來源格式不同，是整個 plugin 架構的地基 |
| **Strategy** | `FingerprintStrategy`、`ThreatScorer` | 評分未來要換 ML；指紋演算法可能升級 |
| **Repository** | 持久化抽象 | 使用 Spring Data 提供的即可，**不要再自己包一層** |
| **Specification** | IOC 複雜查詢、TLP／tenant 過濾 | 使用 JPA 內建 `Specification`，**不要自寫 DSL** |

## 35.2 改用框架內建，不要手刻

| 想用的模式 | 改用 |
|---|---|
| Factory（建立 adapter） | Spring 注入 `List<ThreatSourceAdapter>` 後轉成 Map（§13.2） |
| Observer（事件） | `ApplicationEventPublisher` → Kafka |
| Command（排程任務） | `@Scheduled` 直接呼叫 application service 方法 |
| Builder（一般物件） | Java `record` + 靜態工廠。僅 STIX 物件因欄位多且有條件必填，允許手寫 builder |
| Singleton | Spring bean 預設即是 |

## 35.3 明確禁止（可讀性考量）

| 禁止 | 原因與替代 |
|---|---|
| **Decorator** 用於限流／方案配額 | 堆疊 decorator 會讓 stack trace 難以閱讀、除錯困難。改用單一 `HandlerInterceptor` 或 Spring Security filter |
| **Template Method** 用於 ingestion 流程 | 繼承鏈難以追蹤。改用 §12.2 的明確 stage 列表 |
| **抽象基底類別**（`AbstractXxxService`） | 一律改用組合。介面 + 實作即可 |
| 任何為了「展示模式」而加的抽象 | 違反 §35.0 |
| 自訂 DI 容器、自訂 event bus、自訂 ORM | 重造輪子 |

## 35.4 可讀性硬性規則

- 單一類別 ≤ 300 行
- 單一方法 ≤ 50 行
- 方法參數 ≤ 5 個（超過改用 record 參數物件）
- 巢狀深度 ≤ 3
- 一律建構子注入，**禁止** `@Autowired` 欄位注入
- 公開 API 的 DTO 一律使用 `record`（immutable）
- 禁止循環相依（ArchUnit 驗證）

## 39.3 分頁契約（強制 cursor-based）

IOC 資料量大，offset 分頁在深頁會嚴重劣化。

```text
GET /api/v1/iocs?cursor=<opaque>&limit=50
```

回應：

```json
{
  "items": [ ... ],
  "nextCursor": "eyJscyI6IjIwMjYtMDgtMjBUMTA6MDA6MDBaIiwiaWQiOiIuLi4ifQ==",
  "hasMore": true
}
```

- cursor = base64(JSON of `{sortKey, id}`)，對外不透明
- 排序鍵預設 `(last_seen DESC, id DESC)`
- `limit` 上限依方案（§23.2）
- **僅** UI 需要頁碼時允許 offset，且強制 `offset ≤ 10,000`，超過回 `400 OFFSET_TOO_LARGE`

# 43. RESILIENCY  `[Phase 5 · M1]`

外部來源 adapter 必須支援（使用 Resilience4j）：

| 機制 | 預設值 |
|---|---|
| Timeout | connect 5s / read 30s |
| Retry | 3 次，指數退避（1s、2s、4s），加上 jitter |
| Circuit breaker | 失敗率 50%（滑動視窗 20 次）→ 開啟 60s |
| Bulkhead | 每個來源最多 2 個並行抓取 |

**單一來源故障不得使整個 ingestion 系統停止。** 排程任務逐一處理各來源，互不影響。

# 44. SOURCE HEALTH  `[Phase 5 · M1]`

追蹤：last sync、last success、last failure、連續失敗次數、平均延遲、記錄筆數、狀態。

```text
SourceStatus: ACTIVE | DEGRADED | FAILED | DISABLED
```

轉換規則：

- 連續失敗 3 次 → `DEGRADED`
- 連續失敗 10 次 → `FAILED`，並發出 `SOURCE_FAILURE` 事件
- 一次成功 → 回到 `ACTIVE`
- `DISABLED` 僅由管理員手動設定

# 52. TESTING  `[全 Phase]`

## 52.1 分層策略（重要）

Testcontainers 啟動 Kafka / ES 很慢，必須分層，否則 CI 會變成瓶頸。

| 層級 | 內容 | 何時執行 | 目標時間 |
|---|---|---|---|
| **L1 單元測試** | 純 domain 邏輯，無 Spring context | 每次 push | < 60s |
| **L2 切片測試** | `@WebMvcTest`、`@DataJpaTest`（Testcontainers PostgreSQL） | 每次 push | < 5min |
| **L3 整合測試** | 完整 Spring context + PostgreSQL + Redis | 每次 PR | < 10min |
| **L4 重量整合** | Kafka、Elasticsearch Testcontainers | nightly + release 前 | 不限 |

以 JUnit 5 `@Tag` 標記，Maven profile 控制執行範圍。

## 52.2 後端必須包含

單元測試、repository 測試、service 測試、controller 測試、安全測試、整合測試、adapter 測試、**merge policy 測試**、**正規化測試**、**跨租戶隔離測試**、**TLP 過濾測試**。

## 52.3 覆蓋率門檻

| 模組 | 行覆蓋率下限 |
|---|---|
| `ctip-core/domain` | 85% |
| `ctip-core/application` | 75% |
| `ctip-adapters` | 70% |
| `ctip-app` | 60% |

以 JaCoCo 強制，未達標 CI fail。

## 52.4 ArchUnit 規則（強制）

必須驗證：

1. `domain` 不得依賴 Spring / JPA / Jackson / Kafka / Redis
2. `ctip-sdk` 不得出現 `org.springframework` import
3. `interfaces` 不得 import `infrastructure.persistence`
4. Controller 不得直接依賴 `Repository`
5. 無循環套件相依
6. 所有 `@Service` 使用建構子注入（無 `@Autowired` 欄位）

## 52.5 安全測試（強制）

1. 匿名身分無法取得非 `CLEAR` TLP 的資料
2. Tenant A 無法存取 Tenant B 的任何資源（皆回 404）
3. 過期 token 被拒
4. 撤銷的 refresh token 被拒，且重用會觸發全面撤銷

# 65. FINAL REPOSITORY PRINCIPLE

```text
CTIP
├── environment    → 一份 docker-compose.yml，四種 profile
├── frontend       → React 應用
├── backend        → Spring Boot（4 個 Maven module）
├── docs           → architecture / api / deployment / development
└── .github        → CI/CD
```

同一份程式碼、同一份 Dockerfile 支援所有環境。只有設定、執行行為、secret、資源與部署參數不同。
